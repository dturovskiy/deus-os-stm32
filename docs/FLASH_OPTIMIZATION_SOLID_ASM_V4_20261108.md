## Findings — DRY, cohesion, SOLID and dependency boundaries

1. **Single responsibility (SRP):** `src/kernel.c` ~2,778 lines still mixes composition root, fault/watchdog reporting, UI presentation and CLI dispatch. `scheduler.c` ~1,914 lines combines task kernel, privileged context handling and intrusive self-test logic. `usb_device.c` ~1,619 lines is a peripheral/endpoint state-machine owner. Review each module in bounded steps: split presentation vs kernel composition where it preserves callbacks and object size; avoid moving hot IRQ/state-machine paths into generic interface frameworks. A source-file split without distinct binary-size or maintainability gain has *no guaranteed Flash benefit* and can add calls if inlining is lost.
2. **Open/closed + wire compatibility:** `command_service.c` fixes **39** ordered 1-based RPC descriptors and checked O(1) ID lookup. This deliberate closed registry is a protocol compatibility guarantee; do not reorder/drop IDs for a shorter switch or change SAFE/DIAGNOSTIC/DESTRUCTIVE classification. Full 65,536 ID tests PASS. `binary_frame.c` has fixed wire dimensions, CRC and bounded parser. Keep wire format/version, fail-closed behavior and signed update boundaries invariant.
3. **Interface segregation (ISP):** existing `usb_device` low-level driver vs `usb_management`/Binary RPC and `oled_console` vs `ssd1306` are meaningful separate owners. Do not merge for a single Flash saving estimate. Compartmentalize future USB service options through explicit protocol capability fields, not high-cost universal dispatch per byte. The 39-method registry and the owner-safe hard-DENY for ESP ROM mode remain.
4. **Dependency inversion (DIP):** `scheduler_diagnostics_bindings_t` already injects callback operations and stack boundaries; `ssd1306_set_progress_hook` has a bounded cooperative hook for USART2 RX service *only after closing the I²C transaction*. Reuse these existing contracts rather than creating new heap-based OOP interfaces in firmware. No new high-frequency virtual calls introduced.
5. **Liskov substitution (LSP):** no subtype/class inheritance in the C kernel. Relevant requirement is interface substitutability: `command_service_context_t.write_byte` can succeed/fail without a changed response format; `i2c1_write` failure must leave pending OLED dirty state retryable; `binary_frame` error/noise must preserve correct resync. These were exercised in actual-C mock/regression checks, not asserted from naming.
6. **Code/data dedup:** v3 already shared 118 label+hex+CRLF write sites, saving **1,672 *native* Flash bytes** vs v2 with no test removal. `font5x6.c` and `font5x7.c` already use a contiguous 37-glyph table while `font3x5.c` still had 11 separate 5-byte arrays + switch; the latter is now converted to a single `uint8_t[11][5]` with indexed range mapping. Exact 11 valid glyphs and all 256 `char` values preserve original 5 bytes or NULL. The external pointer address is not a documented identity contract; code/data outputs remain equal. Do not deduplicate 5x6 and 5x7 by transforming pixels at runtime without OLED equivalence/performance proof.
7. **Avoid unproven refactors:** `binary_frame_parser_feed` duplicates some header initialization during normal vs RESYNC states; factoring might reduce source lines but can increase code if not inlined. Its state/error/CRC paths are security-adjacent, so first measure compiler flags before changing it. `usb_device.c` IRQ and flash/antirollback ownership are not size quick wins.
