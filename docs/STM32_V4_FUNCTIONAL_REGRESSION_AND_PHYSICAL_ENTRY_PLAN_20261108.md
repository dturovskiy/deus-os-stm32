## 3. Stack/ISR-specific residual risks

- Scheduler has **two** tasks; production console stack **256 words = 1024 B** with configured min-margin **256 B**; heartbeat stack **128 words = 512 B** with min-margin **256 B** (see \`src/kernel.c\` current source). Cortex-M3 MSP reserve **2048 B**, guard **64 B**, capacity **1984 B**. The \`scheduler.h\` generic \`SCHEDULER_TASK_STACK_WORDS=128\` is a default, not production-console allocation. **Never infer task 512B from generic value when a 1024B production console stack is explicitly bound.**
- Host stack analysis saw \`binary_frame_parser_feed\` frame 0→16B, \`binary_frame_crc16_ccitt_false\` 0→16B, \`binary_frame_finalize_in_place\` 12→16B; \`ssd1306_show_checkerboard\` 24→8B; \`ssd1306_present_stats_get\` 0→8B. Max single positive **+16B**, may compose across nested functions. New \`.su\` entries \`ssd1306_service_progress\`, \`binary_frame_crc16_update\` are compiler codegen decisions; they do **not** mean test functions were deleted/added.
- Need **actual task high-water, canary, MSP current/high-water and watchdog** under real normal workload before hardware runtime PASS. \`mspstat\` and \`schedprod\` existing CLI/RPC methods can provide metrics; do not force destructive \`wdogtrip\` automatically.
- \`USB_LP_CAN1_RX0_IRQHandler\`, privileged \`PendSV\`/SVC and boot update guards unchanged in source/selected flags relative to v3. Link relocation can shift addresses; do not use source equality as measured IRQ latency.
