## Exact current firmware V5

- OS/src/kernel.c initializes Node transport and USART2, but **does not send Node HELLO at boot**. Only an explicit valid node start with a fresh caller-provided nonzero hex8 session ID transmits HELLO.
- Production task0 continues regular legacy UART1 input, USB RPC service, watchdog reload and OLED UI. A separate heartbeat task handles LED and watchdog; neither task requires a successful DNL HELLO/ACK.
- Before a Node session, ready=0 and pending=0; a CRC job is rejected as not ready. No Node failure should propagate to the system boot or legacy USB RPC.
- If ESP is absent after an explicit start, the controller uses a bounded HELLO timeout, at most one retransmission and a Node-only fail-closed state; no endless auto-ping/job transmission in the disconnected state.
- Reopening Node requires a new caller-supplied ID; cross-reboot uniqueness is a **trusted caller obligation**, NOT an intrinsic guarantee, RNG or authentication mechanism.

## Hardware caveat and physical acceptance

Current OS/src/drivers/usart2_node.c enables USART2 at boot with PA3 configured as **floating RX input**. On a physically absent/unpowered ESP, a floating line may create spurious interrupt traffic. Consequently **software optionality is established; physical stability without ESP is NOT_ATTESTED**. A future risk fix may use a GPIO input pull-up or defer RX IRQ until explicit Node start, but this would require new native ARM compilation and Flash/stack reacceptance. Current exact accepted native V5 BIN is 53,044B against ceiling 53,248B, only 204B spare; do not silently modify/sign a different image.
