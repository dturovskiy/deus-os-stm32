## 4. Native stack differences and physical limits

Both old and new native ARM `.su` records were read from their original Windows build directories. There are **298 common** compiler-emitted frames (all old v8 keys still in v4), **20 new** keys (e.g. 5 ESP bridge adapter/functions, shared formatting), **41** common function frame-size differences; most changes are GCC inlining/optimization and newly added bridge layer rather than source-level API removal. Examples: `usb_management_runtime_service` grows from **40→64 B** (+24B), `binary_frame_parser_feed` **0→16 B**, while largest old single function frame `text_renderer_fast_path_self_test` shrinks **272→240 B**. Single-function stack frames do **not** establish nested-stack maximal height or interrupt worst-case; see direct stack audit above. The **actual installed v8** live read-only stack high-water under its own workload is MSP margin1556B, console PSP404B, heartbeat PSP432B, all canaries OK. These numbers **cannot be assigned to v4**, and the installed v8 console margin is close enough to the 256B minimum to warrant full supervised workload/high-water tests if v4 is ever installed.

## 5. Engineering conclusion and unresolved proof

**Verified:** v4 is a full 39-command **expanded** source candidate, not a feature-removal minimalist firmware; all original v8 source paths remain, 63/73 byte-identical. It buys **4,176B Flash** at **+12B static SRAM** and retains tested critical code. Offline v4 tests for all 11 font glyphs/256 char values, all-day OLED full buffer 11,520 cases, 28 SSD1306/I2C mock scenarios, 270,748 bytes Binary Frame protocol differential, 39/65536 method IDs, USB Management ESP hard-DENY, NodeLink and watchdog MMIO simulation all PASS, plus original Windows ARM resource PASS. **No new native v8/v4 live USB wire equality test was run**.

**Not verified:** on-device execution of v4, compatibility of every command payload under physical timing, USB enumeration, IRQ latency, OLED I²C live, ESP bridge ROM programming, actual v4 MSP/PSP high-water, signed-v9 floor/admission and rollback. The owner approved ONLY read-only physical tests of installed signed v8, which passed; signing/Flash/reset require a new explicit authorization. **`P1_INSTALLED_V8_BASELINE=ACCEPTED_SCOPED`, `V4_PHYSICAL=NOT_ATTESTED`, `Gate4=NOT_AUTHORIZED`**.

**Decision:** stop treating v8 and v4 as two identical binaries. Adopt v4 as **native resource + offline functional candidate** and v8 as **measured live physical baseline**; keep their separately labeled Evidence. Next qualification predicates must be owner-approved, source-locked, protected signed image+recovery and physical v4 tests, not a blind swap.
