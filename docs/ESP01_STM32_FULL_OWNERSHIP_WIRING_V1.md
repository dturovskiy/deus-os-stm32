# ESP-01: повне керування від STM32 — схема з'єднань V1

**Статус:** інженерна електрична схема для майбутнього монтажу; **на поточному стенді НЕ ЗІБРАНО**. Це не свідчення монтажу, не команда на перепідключення і не дозвіл на Flash. Поточні перевірені A2 (PA2, USART2_TX) та A3 (PA3, USART2_RX) залишаються без змін. Конкретний GPIO-профіль B0 (PB0) / B1 (PB1) відповідає вже написаному `esp_gpio_board_v0.c`.

## Електричні мережі

```text
          Один вхід 5 V від STM32 USB (із перевіреним бюджетом струму)
                            |
                   окремий стабілізатор
                     3.3 V >= 500 mA
                            |
                     ESP_3V3 (3.3 V)
                      |    |     |
                    10uF  100nF  bulk, поруч із ESP-01
                      |    |     |
GND (спільна) --------+----+-----+--------------------------------+
                            |                                     |
                        ESP-01                                    |
 STM32 A2 (PA2 USART2_TX) --[470R..1k, optional]--> ESP RXD       |
 STM32 A3 (PA3 USART2_RX) <--[470R..1k, optional]--- ESP TXD       |
 STM32 B0 (PB0 open-drain) ------------------------> ESP GPIO0    |
                                                 |              |
                                      10k pull-up to ESP_3V3     |
 STM32 B1 (PB1 open-drain) ------------------------> ESP EN/CH_PD |
                                                 |              |
                                      10k pull-up to ESP_3V3     |
 ESP GPIO2 ---------------- 10k pull-up to ESP_3V3               |
 ESP GND --------------------------------------------------------+
```

Схема використовує **дві окремі функції**: UART-дані через PA2/PA3 і BOOT/EN через PB0/PB1. PB0/PB1 — вибраний профіль **для поточного драйвера**, але монтаж/електрична сумісність цих виводів не підтверджені. STM32 не живить ESP своїм GPIO. GPIO0, EN мають апаратні підтяжки до **того самого** ESP_3V3, а STM32 налаштований лише як open-drain LOW / release.

## Обов'язкове відокремлення чинного USB-UART/CH340

Перед застосуванням цього профілю на фізичному стенді ESP VCC, GPIO0 і EN **більше не мають приводитися від CH340**; CH340 TX/RX вже не є каналом даних. Не допускаються два одночасні виходи на GPIO0/EN, дві незалежні 3.3 V лінії чи backfeed між USB. Потрібна **одна** перевірена ESP_3V3 шина із спільним GND. Наявний CH340 зберігається без змін, доки схему не змонтовано.

На STM32F103C8 ці мережі зарезервовані: SWDIO (PA13), SWCLK (PA14), USB A11 (PA11) / A12 (PA12), OLED B6 (PB6) / B7 (PB7), USART1 A9 (PA9) / A10 (PA10), C13 (PC13). PB0/PB1 фізично вільні за перевіреним кодом, але це **не вимір схеми плати**.

## Стани та recovery

| Стан | PB0→GPIO0 | PB1→EN | Наслідок |
|---|---|---|---|
| STM32 reset / pins high-Z | HIGH через 10k | HIGH через 10k | ESP звичайне завантаження, без примусового ROM |
| Звичайна робота | release | release | ESP застосунок, NodeLink через USART2 |
| ROM: старт | LOW | LOW мін. 20 ms | ESP зупинений, GPIO0=0 |
| ROM: перехід | LOW | release, чекати мін. 100 ms | ESP ROM bootloader, UART0 через STM32 |
| Звичайне завантаження після штатного CLOSE | release | LOW мін. 20 ms, далі release і 100 ms | ESP застосунок; READY лише після нового HELLO |
| Невизначений USB/UART/Flash результат | release | **LOW** | Fail-closed; зупинено до явного recovery |

**Непрацездатний ESP-застосунок не повинен блокувати ROM recovery**. Дозвіл на перехід у ROM походить від локально затвердженого профілю плати, не від позитивного HELLO. Саме це реалізовано у новому `esp_boot_control_v0_recovery_rom_start`. USB-повідомлення не може встановити `DEUS_ESP_STM32_BOARD_QUALIFIED`.

**Історична normal10; чинний фізичний стенд normal13 і підготовлена normal14** із GPIO0/EN під CH340 мають використовувати `DEUS_ESP_STM32_BOARD_QUALIFIED=0`: майбутній PB0/PB1-контролер інертний і не торкається GPIO. Поточний розділений USB/USART2 міст — окремий механізм, тому його `OPEN` не слід називати завжди відхиленим.

## Межі доказів та сумісності

Внутрішній ESP8266 flash bootstrap потребує GPIO0 LOW для ROM завантаження, GPIO2 HIGH і відповідного стану GPIO15 (на ESP-01 модуль зазвичай має фабричний strap; підтвердити модифікацію модуля при монтажі). EN має бути HIGH для роботи, LOW для reset. Зв'язок 115200 8N1 на PA2/PA3 уже фізично доведений для DNL, **не для ROM після нового монтажу**.

Оригінальний ESP 1 MiB Flash backup SHA `8F1DCEE6162AA734FDD9A09A5B116062103E796D1787E77A60E7690608912E96` та ESP Wi-Fi app-only BIN SHA `541FB4F3A102685611E839A21F689098392C74542EDC53B88C4128EB2FE82070` є окремими існуючими файлами; ця схема не перепрошиває їх. Старі bootloader `0x00000` і partitions `0x08000` не оновлювати замість застосунку `0x10000`.

**До монтажу** вже виконано офлайн нативну ARM-збірку обох профілів: OFF 52 284 Б Flash / 8 592 Б SRAM; QUALIFIED 52 864 Б Flash / 8 608 Б SRAM, запас Flash 384 Б (GNU ARM14.2.1, Mac mini, синтетична ідентичність без підпису). Це **не дозвіл встановлювати QUALIFIED на нинішню плату**, де CH340 досі керує BOOT/EN. Фізична реалізація цієї схеми, підписаний реліз, перевірка ESP ROM SYNC і Wi-Fi Flash залишаються невиконаними. Кінцева ціль — **один USB Mac→STM32, без CH340 у робочій системі**.
